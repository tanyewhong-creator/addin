# A/addin Copy Style Guide

Voice rules for every user-facing string in addin overlay code. Enforced by code review (no automated linter for prose).

## Voice & posture

- Plainspoken, technical. No AI-marketing fluff: no "supercharge", no "revolutionize", no rocket emojis.
- Show, don't sell. Concrete capability statements > abstract promise.
- Mythic undertone, serious infrastructure product. The Aladdin etymology stays in the README origin line and nowhere else.

## Mechanics

- Lowercase by default. Capital letters reserved for proper nouns and the leading "A" in the wordmark.
- No exclamation marks.
- No emoji.
- Forbidden words/phrases: "magic", "wishes", "genie", "sparkles", "your three wishes".
- Second-person preferred over imperatives: *"you can change this later"* over *"change this later"*.
- Numerical scarcity in lists: roman numerals or numbers on the marketing site, plain bullets in CLI output.
- The agent's first-person `i` is permitted on Telegram and dashboard nudges; CLI and other dashboard surfaces use neutral third-person ("addin captured a skill", not "i captured a skill").

## Pronunciation

A/addin is read as "Aladdin" (uh-LAD-in). The slash is a visual brand device, never spoken.
- ✅ "Welcome to Aladdin 2.0"
- ❌ "Welcome to slash addin"
